ROLE
You are a senior creative developer with 15+ years of experience. Build "Scramble Label Button": mono-spaced buttons whose labels scramble through glyphs and lock in left to right while a lime wipe fills the shell.

GOAL
One self-contained HTML file that looks like part of a funded product's real interface — specific, considered and never a generic template.

ART DIRECTION
- Mood: Terminal black with a faint grid, acid lime, bone white and signal red.
- Palette: #E6EBDD, #BEF264, #FB7185, #0B0D0A, #7C8672
- Type: JetBrains Mono, Space Grotesk (loaded from Google Fonts via <link>)
- Theme: dark

ANATOMY
- Headline and intro; three full-width buttons with index numbers: primary, neutral and destructive.

INTERACTION & STATES
- On hover or focus the label cycles random glyphs and locks characters progressively; a wipe slides in from the left; reduced motion skips the scramble.
- Every interactive element has a visible :focus-visible state and a sensible hover/active state.

MOTION SPEC (exact values, do not approximate)
- Glyph pool: A-Z, 0-9 and #$%&*+<>/\=. One character locks every 2.2 frames, left to right; spaces never scramble.
- Unlocked glyphs render at 55% opacity inside a fixed-width span so the label never changes width.
- Wipe fill: translateX(-101% to 0) over 350ms cubic-bezier(.7,0,.2,1).

IDLE AUTOPLAY
- The highlight walks down the three buttons every 2.4s and re-decodes the active label.
- Autoplay stops permanently on the first real pointer, touch or key event and is fully disabled under prefers-reduced-motion.

AVOID (these make it generic)
- Random characters with proportional glyphs that make the button jitter.
- Scramble that never resolves to the exact final string.

CONSTRAINTS
- Single HTML file with inline CSS (and only the small amount of vanilla JS the behaviour needs). No frameworks, no build step.
- Inline SVG icons only — no emoji, no stock imagery. Real, specific copy; no lorem ipsum.
- Responsive from 360px up; honour prefers-reduced-motion; keep text contrast at WCAG AA or better.
- Semantic HTML with proper roles/labels where the component is interactive.

ACCEPTANCE CHECKLIST
- No layout shift, overflow or clipped text at 1440px and 390px.
- Every state described above is reachable and looks intentional.
- It could not be mistaken for a different component or another product's default styling.
