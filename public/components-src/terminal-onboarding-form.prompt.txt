ROLE
You are a senior developer-tools designer and front-end engineer with 15+ years of experience. Build "Terminal Onboarding Form": a project setup flow rendered as a CLI: typed answers, arrow-key option lists, a progress bar and a ready message, fully operable from the keyboard.

GOAL
One self-contained HTML file that looks like part of a funded product's real interface — specific, considered and never a generic template.

ART DIRECTION
- Mood: Ink-black terminal window with sky-blue prompts, emerald confirmations and JetBrains Mono.
- Palette: #38BDF8, #34D399, #6B7A8F, #0A0C10, #D7E0EA, #0F131A
- Type: JetBrains Mono, Inter Tight (loaded from Google Fonts via <link>)
- Theme: dark

ANATOMY
- Window chrome; banner; answered questions with check marks; the active prompt with caret or option list; install progress and next-step commands.

INTERACTION & STATES
- Click the terminal to take over: type for text prompts, Up and Down plus Enter for option lists, Backspace edits; finishing runs the install bar and prints the ready message.
- Every interactive element has a visible :focus-visible state and a sensible hover/active state.

MOTION SPEC (exact values, do not approximate)
- Caret blinks on a 1s steps(1) loop; progress bar width eases over 300ms in 9 percent steps.

IDLE AUTOPLAY
- An autopilot types the project name at 85ms per key, moves the selection with arrow presses, answers all four prompts, runs the install and loops after showing the result.
- Autoplay stops permanently on the first real pointer, touch or key event and is fully disabled under prefers-reduced-motion.

AVOID (these make it generic)
- A screenshot of a terminal; every line is live text.
- Mouse-only controls; the whole flow works from the keyboard.

CONSTRAINTS
- Single HTML file with inline CSS (and only the small amount of vanilla JS the behaviour needs). No frameworks, no build step.
- Inline SVG icons only — no emoji, no stock imagery. Real, specific copy; no lorem ipsum.
- Responsive from 360px up; honour prefers-reduced-motion; keep text contrast at WCAG AA or better.
- Semantic HTML with proper roles/labels where the component is interactive.

ACCEPTANCE CHECKLIST
- No layout shift, overflow or clipped text at 1440px and 390px.
- Every state described above is reachable and looks intentional.
- It could not be mistaken for a different component or another product's default styling.
