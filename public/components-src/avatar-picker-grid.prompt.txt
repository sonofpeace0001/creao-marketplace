ROLE
You are a senior onboarding designer and front-end engineer with 15+ years of experience. Build "Avatar Picker Grid": a twelve-avatar picker where one shared selection ring glides between tiles while the large preview swaps and its glow takes on the avatar's colour.

GOAL
One self-contained HTML file that looks like part of a funded product's real interface — specific, considered and never a generic template.

ART DIRECTION
- Mood: Deep aubergine card with a violet glow, saturated per-avatar accents and softly desaturated unselected tiles.
- Palette: #A855F7, #1B1530, #14101F, #F1ECFF, #9A8FC4
- Type: Bricolage Grotesque, DM Mono (loaded from Google Fonts via <link>)
- Theme: dark

ANATOMY
- Preview column with large avatar, name, index and Use this avatar button; grid of twelve radio-style avatar tiles with a single ring element.

INTERACTION & STATES
- Radiogroup semantics; choosing a tile moves the ring with a spring, updates name, index and accent colour and swaps the preview with a pop.
- Every interactive element has a visible :focus-visible state and a sensible hover/active state.

MOTION SPEC (exact values, do not approximate)
- Ring translates 500ms cubic-bezier(.3,1.4,.4,1); preview in: scale 1.25 to 1 over 550ms; out: scale .8 over 300ms; glow colour transitions 500ms; unselected tiles at .7 saturation.

IDLE AUTOPLAY
- The ring moves to a new tile every 1.5s.
- Autoplay stops permanently on the first real pointer, touch or key event and is fully disabled under prefers-reduced-motion.

AVOID (these make it generic)
- A ring per tile that cross-fades; one shared ring conveys movement.
- Colour as the only selection signal; the ring and full saturation both change.

CONSTRAINTS
- Single HTML file with inline CSS (and only the small amount of vanilla JS the behaviour needs). No frameworks, no build step.
- Inline SVG icons only — no emoji, no stock imagery. Real, specific copy; no lorem ipsum.
- Responsive from 360px up; honour prefers-reduced-motion; keep text contrast at WCAG AA or better.
- Semantic HTML with proper roles/labels where the component is interactive.

ACCEPTANCE CHECKLIST
- No layout shift, overflow or clipped text at 1440px and 390px.
- Every state described above is reachable and looks intentional.
- It could not be mistaken for a different component or another product's default styling.
