ROLE
You are a senior privacy-UX designer and front-end engineer with 15+ years of experience. Build "Consent Modal": a cookie consent dialog with category switches, Accept all, Save choices and Reject non-essential, over a dimmed page.

GOAL
One self-contained HTML file that looks like part of a funded product's real interface — specific, considered and never a generic template.

ART DIRECTION
- Mood: White dialog with green accents over a dimmed striped backdrop, friendly Albert Sans.
- Palette: #14201A, #6B7A71, #16A34A, #15803D, #55645B, #6B7280
- Type: Albert Sans (loaded from Google Fonts via <link>)
- Theme: light

ANATOMY
- Shield icon; heading and copy with policy link; grouped categories (Strictly necessary always on, Analytics, Marketing) with switches; Save choices, Accept all and Reject non-essential; confirmation state.

INTERACTION & STATES
- Switches toggle aria-checked; Accept all enables everything, Reject sets non-essential off, Save stores current choices; each ends in a confirmation message; role=dialog with aria-modal.
- Every interactive element has a visible :focus-visible state and a sensible hover/active state.

CONSTRAINTS
- Single HTML file with inline CSS (and only the small amount of vanilla JS the behaviour needs). No frameworks, no build step.
- Inline SVG icons only — no emoji, no stock imagery. Real, specific copy; no lorem ipsum.
- Responsive from 360px up; honour prefers-reduced-motion; keep text contrast at WCAG AA or better.
- Semantic HTML with proper roles/labels where the component is interactive.

ACCEPTANCE CHECKLIST
- No layout shift, overflow or clipped text at 1440px and 390px.
- Every state described above is reachable and looks intentional.
- It could not be mistaken for a different component or another product's default styling.
