ROLE
You are a senior motion designer and front-end engineer with 15+ years of experience. Build "Gooey FAB Menu": a floating action button whose four actions pull out of one drop through an SVG goo filter and snap back into it.

GOAL
One self-contained HTML file that looks like part of a funded product's real interface — specific, considered and never a generic template.

ART DIRECTION
- Mood: Deep aubergine with hot pink liquid blobs and white line icons.
- Palette: #9A86B8, #FF4D8D, #12091F, #F3EBFF
- Type: Unbounded, Manrope (loaded from Google Fonts via <link>)
- Theme: dark

ANATOMY
- Headline and intro; a single plus toggle with four action bubbles in an arc: document, image, voice note, invite.

INTERACTION & STATES
- A blur plus alpha-threshold filter merges the blobs while they spring out with staggered delays; the plus rotates to a cross; Escape closes; actions are keyboard focusable menu items.
- Every interactive element has a visible :focus-visible state and a sensible hover/active state.

MOTION SPEC (exact values, do not approximate)
- Filter: feGaussianBlur stdDeviation 10 then feColorMatrix alpha row '0 0 0 20 -9' then blend with the source.
- Bubbles spring out 600ms cubic-bezier(.3,1.5,.5,1), staggered 50ms; plus rotates 135 degrees.
- Arc offsets (px): (-90,-44), (-46,-98), (46,-98), (90,-44); bubble 68px, main 84px.

IDLE AUTOPLAY
- The menu breathes open and shut every 2.8s until the toggle is pressed.
- Autoplay stops permanently on the first real pointer, touch or key event and is fully disabled under prefers-reduced-motion.

AVOID (these make it generic)
- Filtering the icons: apply goo to the blob layer only so glyphs stay crisp.
- Bubbles that never overlap, which defeats the metaball merge.

CONSTRAINTS
- Single HTML file with inline CSS (and only the small amount of vanilla JS the behaviour needs). No frameworks, no build step.
- Inline SVG icons only — no emoji, no stock imagery. Real, specific copy; no lorem ipsum.
- Responsive from 360px up; honour prefers-reduced-motion; keep text contrast at WCAG AA or better.
- Semantic HTML with proper roles/labels where the component is interactive.

ACCEPTANCE CHECKLIST
- No layout shift, overflow or clipped text at 1440px and 390px.
- Every state described above is reachable and looks intentional.
- It could not be mistaken for a different component or another product's default styling.
