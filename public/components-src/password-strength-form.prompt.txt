ROLE
You are a senior security-minded product designer and front-end engineer with 15+ years of experience. Build "Password Strength Form": a create-password form with a four-segment strength meter, a live rule checklist that ticks itself off and an honest crack-time estimate.

GOAL
One self-contained HTML file that looks like part of a funded product's real interface — specific, considered and never a generic template.

ART DIRECTION
- Mood: Midnight violet card, an accent colour that shifts from rose through amber to emerald with strength, mono password text.
- Palette: #8D86B3, #0E0B1A, #ECE9FA, #7C5CFF, #15112A, #34D399
- Type: Inter Tight, JetBrains Mono (loaded from Google Fonts via <link>)
- Theme: dark

ANATOMY
- Heading and intro; labelled password field with an animated show/hide eye; four meter segments; strength label with crack-time estimate; four rules (12 characters, mixed case, number, symbol); Continue button disabled until strong.

INTERACTION & STATES
- Each keystroke re-scores the password and recolours the card accent; rules tick with a drawn checkmark; the eye icon draws a slash through itself when the password is revealed; Continue unlocks only at four rules.
- Every interactive element has a visible :focus-visible state and a sensible hover/active state.

MOTION SPEC (exact values, do not approximate)
- Meter segments scaleX 0 to 1 from the left, 400ms cubic-bezier(.3,1.2,.4,1); rule dots spring to 1.08 scale as the check draws via stroke-dashoffset 18 to 0 over 350ms.
- Eye slash: stroke-dasharray 26 animating over 300ms.
- Accent colours by score: #F43F5E, #F97316, #FACC15, #84CC16, #34D399.

IDLE AUTOPLAY
- Four progressively stronger passwords (harbour, Harbour7, Harbour7!, Tidal-Harbour7!) are typed at 110ms per character with the field revealed, then it loops.
- Autoplay stops permanently on the first real pointer, touch or key event and is fully disabled under prefers-reduced-motion.

AVOID (these make it generic)
- A meter that only changes colour; segments must fill one by one.
- Claiming fake precision; crack-time copy is an estimate and says so.
- Checklist ticks that appear instantly with no drawn check.

CONSTRAINTS
- Single HTML file with inline CSS (and only the small amount of vanilla JS the behaviour needs). No frameworks, no build step.
- Inline SVG icons only — no emoji, no stock imagery. Real, specific copy; no lorem ipsum.
- Responsive from 360px up; honour prefers-reduced-motion; keep text contrast at WCAG AA or better.
- Semantic HTML with proper roles/labels where the component is interactive.

ACCEPTANCE CHECKLIST
- No layout shift, overflow or clipped text at 1440px and 390px.
- Every state described above is reachable and looks intentional.
- It could not be mistaken for a different component or another product's default styling.
