ROLE
You are a senior event brand designer and front-end engineer with 15+ years of experience. Build "Ticket Stub Card": an event ticket with real notched perforations, a barcode under a scanning laser and a stub that tears away on hover.

GOAL
One self-contained HTML file that looks like part of a funded product's real interface — specific, considered and never a generic template.

ART DIRECTION
- Mood: Warm cream table, vermilion ticket with a diagonal micro pattern and a black stub, mono data labels.
- Palette: #FFF3E6, #201712, #FF5A36, #F2E6D4
- Type: Unbounded, Archivo, Space Mono (loaded from Google Fonts via <link>)
- Theme: light

ANATOMY
- Main panel: admit-one line, number, festival name, date and venue, doors/gate/tier; stub: rotated event label, section, barcode with laser; Scan at the gate button.

INTERACTION & STATES
- Hover or the button tears the stub (rotate 7 degrees, shift 12px and 6px) and it springs back on leave.
- Every interactive element has a visible :focus-visible state and a sensible hover/active state.

MOTION SPEC (exact values, do not approximate)
- Tear: 800ms cubic-bezier(.3,1.3,.4,1) from the bottom-left corner of the stub.
- Laser: 3px glow line travelling 2% to 94% of the barcode over 2.4s ease-in-out forever.
- Notches via radial-gradient masks, 14px radius, on both halves.

IDLE AUTOPLAY
- The stub tears and re-attaches every 1.9s after a 3.6s head start; the laser never stops.
- Autoplay stops permanently on the first real pointer, touch or key event and is fully disabled under prefers-reduced-motion.

AVOID (these make it generic)
- Fake notches drawn as white circles; they must be true cut-outs.
- A barcode that is just a grey rectangle.

CONSTRAINTS
- Single HTML file with inline CSS (and only the small amount of vanilla JS the behaviour needs). No frameworks, no build step.
- Inline SVG icons only — no emoji, no stock imagery. Real, specific copy; no lorem ipsum.
- Responsive from 360px up; honour prefers-reduced-motion; keep text contrast at WCAG AA or better.
- Semantic HTML with proper roles/labels where the component is interactive.

ACCEPTANCE CHECKLIST
- No layout shift, overflow or clipped text at 1440px and 390px.
- Every state described above is reachable and looks intentional.
- It could not be mistaken for a different component or another product's default styling.
