ROLE
You are a senior auth product designer and front-end engineer with 15+ years of experience. Build "Magic Link Form": a passwordless sign-in card with a floating label, inline validation, a loading button and a transition to an animated envelope with a resend countdown.

GOAL
One self-contained HTML file that looks like part of a funded product's real interface — specific, considered and never a generic template.

ART DIRECTION
- Mood: Warm cream paper with burnt-orange accent, serif headline and a hand-built envelope illustration.
- Palette: #E8590C, #2B2018, #9C8A79, #DC2626, #7F6E5F, #FFF7EA
- Type: Fraunces, Figtree (loaded from Google Fonts via <link>)
- Theme: light

ANATOMY
- Phase one: serif headline, intro, floating-label email field, error line, Send button with spinner, fine print; phase two: envelope whose flap opens and letter rises, confirmation copy with the address, resend control with 30 second countdown.

INTERACTION & STATES
- Invalid email shakes the field and shows a specific message; valid email shows a spinner for 1.1s then slides phase one up and phase two in; Resend returns to the form.
- Every interactive element has a visible :focus-visible state and a sensible hover/active state.

MOTION SPEC (exact values, do not approximate)
- Phase slide: translateY 100% to 0 over 600ms cubic-bezier(.7,0,.2,1) with a 400ms fade.
- Envelope flap rotateX 0 to 180 degrees over 450ms; letter translateY -34px over 700ms after a 350ms delay, spring cubic-bezier(.3,1.4,.4,1).
- Floating label: 220ms to 11px uppercase orange.

IDLE AUTOPLAY
- After 3.6s an address is typed at 95ms per character, submitted, the inbox state shows for about 4s, then it resets and repeats.
- Autoplay stops permanently on the first real pointer, touch or key event and is fully disabled under prefers-reduced-motion.

AVOID (these make it generic)
- Success shown as a plain green tick; the envelope is the moment.
- Validation that only says 'invalid'; the message names the expected format.

CONSTRAINTS
- Single HTML file with inline CSS (and only the small amount of vanilla JS the behaviour needs). No frameworks, no build step.
- Inline SVG icons only — no emoji, no stock imagery. Real, specific copy; no lorem ipsum.
- Responsive from 360px up; honour prefers-reduced-motion; keep text contrast at WCAG AA or better.
- Semantic HTML with proper roles/labels where the component is interactive.

ACCEPTANCE CHECKLIST
- No layout shift, overflow or clipped text at 1440px and 390px.
- Every state described above is reachable and looks intentional.
- It could not be mistaken for a different component or another product's default styling.
