ROLE
You are a senior admin-UI designer and front-end engineer with 15+ years of experience. Build "Permission Group": a role-permissions checklist with a tri-state Select all, live count and a Save button that disables when empty.

GOAL
One self-contained HTML file that looks like part of a funded product's real interface — specific, considered and never a generic template.

ART DIRECTION
- Mood: Graphite panel with green checks and mono metadata; precise and enterprise-calm.
- Palette: #4ADE80, #7B879B, #0D1117, #1B2230, #06140B, #090B0F
- Type: Albert Sans, JetBrains Mono (loaded from Google Fonts via <link>)
- Theme: dark

ANATOMY
- Header with role context; 'All permissions' master checkbox with count; five permission rows with title and description; footer with summary and Save role.

INTERACTION & STATES
- The master checkbox is checked, unchecked or indeterminate based on children and toggles them all.
- Save is disabled with zero selected and confirms with a brief 'Saved' state; native checkboxes with visible focus.
- Every interactive element has a visible :focus-visible state and a sensible hover/active state.

CONSTRAINTS
- Single HTML file with inline CSS (and only the small amount of vanilla JS the behaviour needs). No frameworks, no build step.
- Inline SVG icons only — no emoji, no stock imagery. Real, specific copy; no lorem ipsum.
- Responsive from 360px up; honour prefers-reduced-motion; keep text contrast at WCAG AA or better.
- Semantic HTML with proper roles/labels where the component is interactive.

ACCEPTANCE CHECKLIST
- No layout shift, overflow or clipped text at 1440px and 390px.
- Every state described above is reachable and looks intentional.
- It could not be mistaken for a different component or another product's default styling.
